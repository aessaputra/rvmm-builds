# AGENTS.md

Guidance for coding agents working in this repository. Written following
[agents.md](https://agents.md/) and derived from the repository contents, not
from assumptions.

## Project Overview

Personal fork of [`j-hc/revanced-magisk-module`](https://github.com/j-hc/revanced-magisk-module)
(`aessaputra/rvmm-builds`) that builds ReVanced/Morphe APKs for 12 Android apps
and publishes the results to GitHub Releases.

The pipeline:

```
config.toml (12 app tables)
  -> build.sh             read config, loop over tables
  -> utils.sh             fetch stock APK, fetch patch bundle + CLI, patch, align, sign
  -> build/               <app>-<brand>-v<version>-<arch>.apk + module zips
  -> GitHub Actions       release + update json + Telegram notification
```

All logic is shell. `build.sh` is a thin orchestrator (175 lines); `utils.sh`
(909 lines) holds every worker function. No other language, no test suite, no
package manager.

Components:

- `build.sh` — entry point. Validates tools (`jq`, `java`, `zip`), reads
  `config.toml` via `bin/toml/tq-*`, loops over tables, calls `build_rv` per
  app. Special modes: `./build.sh clean` (remove `temp/`, `build/`, `build.md`)
  and `./build.sh <cfg> --config-update` (print apps that have new versions).
- `utils.sh` — key functions: `build_rv` (core build), `get_prebuilts`
  (download/cache patch bundle + CLI), `patches_list` /
  `get_patch_last_supported_ver` (find the version supported by the patches),
  `dl_archive` / `dl_apkmirror` / `dl_uptodown` / `dl_direct` (stock APK
  sources), `merge_splits` (APKM/XAPK -> APK), `patch_apk`, `check_sig`,
  `module_prop`.
- `config.toml` — one table per app: `pkg-name`, `patches-source`,
  `cli-source`, `rv-brand`, `archive-dlurl`, `apkmirror-dlurl`, etc.
- `CONFIG.md` — documents every config key and its default.
- `module/` — Magisk/KernelSU module template (`customize.sh`, `service.sh`,
  `module.prop` is generated by `module_prop`).
- `bin/` — committed helper binaries: `aapt2`, `htmlq`, `toml/tq`,
  `apksigner.jar`, `dexlib2.jar`, `paccer.jar`. Do not delete; CI uses them.
- `sig.txt` — sha256 of the expected signing certificate per package.
  `check_sig` uses it to confirm a stock APK is genuine (only for listed
  packages).
- `ks.keystore`, `ks-p12.keystore` — signing keys for build outputs.

## Setup Commands

This repository is designed for GitHub Actions (Ubuntu + JDK 21). Locally,
`build.sh` requires:

```bash
jq --version   # required, checked at the start of build.sh
java --version # required, JDK 21 (used by apksigner + morphe-cli)
zip --version  # required, for modules
unzip --version
git, curl, gh  # prebuilt downloads + releases
```

Linux:

```bash
git clone https://github.com/aessaputra/rvmm-builds
cd rvmm-builds
./build.sh
```

Termux: `bash build-termux.sh`.

Rootless hosts (e.g. an aarch64 container): `bin/aapt2`, `bin/htmlq`, `bin/toml`
already ship arm64/arm builds. Java and zip must be provided separately.

## Development Workflow

1. Change `config.toml` (not `build.sh`) to add an app, switch a patch source,
   or change the stock APK source.
2. Validate shell syntax after touching `build.sh` / `utils.sh`:
   `bash -n build.sh && bash -n utils.sh`.
3. Check for new versions without building:
   `./build.sh config.toml --config-update` (needs `build.md`; prints the apps
   that need a build, or nothing when there is nothing new).
4. Full local build: `./build.sh` (writes `temp/`, `build/`, `build.md`).
5. Remove artifacts: `./build.sh clean`.

Note: `parallel-jobs` is forced to `1` in `build.sh` (comment: multiple jobs
were broken by recent CLI versions). Do not "fix" that without testing the CLI.

## Testing Instructions

There is no unit test suite. Available verification:

- `bash -n build.sh && bash -n utils.sh` — syntax gate, run after every shell
  change.
- `./build.sh config.toml --config-update` — exercises config parsing and
  version checks without patching. Cheapest way to confirm `config.toml` is
  still valid.
- Build a single app: set `enabled = false` on the other tables, then
  `./build.sh`. Output lands in `build/`; read `build.md` for the per-app log.
- Expected failure modes visible in `build.md`: `Could not find <app> in
  archive` means the stock version is missing from the archive, not a code bug.

## Code Style

- Bash with `set -euo pipefail`; tab indentation; `snake_case` function names.
- Emit messages through the helpers: `pr` (info), `epr` (error, also emits
  `::error::` on Actions), `wpr` (warning), `abort` (stop all jobs), `log`
  (append to `build.md`, which becomes the release body).
- Do not `echo` status messages directly; CI parses `::error::` /
  `::warning::`.
- Read config values with `toml_get "$t" <key> || default`, never hand-parse.
- Output filenames are decided by `build_rv`; do not change the pattern because
  `*-update.json` and the workflow depend on it.

## Build and Deployment

- Main CI: `.github/workflows/ci.yml` — daily cron `0 16 * * *` plus
  `workflow_dispatch`. Job `check` runs `--config-update`; only when a new
  version exists does the `build` job (`.github/workflows/build.yml`) run.
- `build.yml` uses JDK 21 (zulu), checks out `origin/update` for `build.md`,
  builds, creates or edits the numbered release (`NEXT_VER_CODE`), writes
  `*-update.json` to the `update` branch, then posts a Telegram notification
  when `TG_TOKEN` is set.
- Builds run automatically. Do not trigger `workflow_dispatch` manually unless
  asked; just make sure the stock APK is available.
- Outputs: `build/<app>-<brand>-v<version>-<arch>.apk` and
  `build/<module>-<brand>-v<version>.zip`. Both are gitignored.
- Stock APKs are fetched in order from `DL_SRCS=("direct" "archive"
  "apkmirror")`. Most apps use `archive-dlurl` pointing at the archive.org item
  `km-apks` with the pattern `apks/<pkg>/<pkg>-<version>-all.apk`. When a file
  is missing there, the build falls back to `apkmirror-dlurl`.

## Adding a new app

1. Add a table to `config.toml`:

   ```toml
   [AppName]
   app-name = "App Name"
   patches-source = "org/repo-patches"
   cli-source = "MorpheApp/morphe-cli"
   rv-brand = "Brand"
   build-mode = "apk"
   pkg-name = "com.example.app"
   apkmirror-dlurl = "https://www.apkmirror.com/apk/vendor/app/"
   archive-dlurl = "https://archive.org/download/km-apks/apks/com.example.app"
   ```

2. Make sure the stock APK for the version supported by the patches exists in
   the archive. If not, upload it to `km-apks` as
   `apks/<pkg>/<pkg>-<version>-all.apk` (APKM/XAPK is fine as long as the
   extension is `.apkm` so `merge_splits` runs).
3. Do not modify `build.sh` for a new app. All per-app behavior is driven by
   config keys (`CONFIG.md`).

## Pull Request Guidelines

- Title format: `type: summary` (`feat:`, `fix:`, `chore:`, `refactor:`),
  matching the existing history.
- Include `bash -n` output for changed shell files and the `--config-update`
  result when `config.toml` changes.
- Never commit `build/`, `temp/`, `build.md`, `*.apk`, `*.zip` (already
  gitignored).
- Never commit new keystore files or change `sig.txt` without a clear reason.

## Security Considerations

- `ks.keystore` and `ks-p12.keystore` are signing keys. Do not replace, move,
  or print their contents.
- `sig.txt` binds a package to a sha256 certificate. `check_sig` uses
  `apksigner verify --print-certs`; do not weaken that check.
- Stock APKs from third-party sources (personal archive, APKMirror, APKPure)
  must be treated as untrusted. Patching and re-signing are the defense; never
  skip `check_sig` for a listed package.
- CI secrets: `GITHUB_TOKEN` (built in), `TG_TOKEN` + `TG_CHAT` (optional,
  Telegram notification: bot token and destination chat). Never write tokens
  or chat ids into committed files.

## Troubleshooting

- `Could not find <app> in archive` — the version the patches need is not in
  `km-apks`; upload the stock APK, do not change code.
- `All builds failed` — every table failed; read `build.md` and verify the
  tools (`jq`, `java`, `zip`).
- archive.org metadata lags a few minutes after an upload, so the download URL
  can 404 briefly. Wait; do not re-upload.
- `Patching integrations checks failed` on non-ReVanced apps (e.g. TikTok
  Hushfeed) is a warning that can be ignored.
- `enable-update-checks` only applies to the j-hc scheme; for other apps the
  flag is ignored.
